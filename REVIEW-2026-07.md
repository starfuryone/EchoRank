# Echorank product review — 2026-07-28

Read-only audit of `/opt/echorank/app` (+ `av-service`, `extension-dist`, `extension/`).
Nothing was modified. Every claim cites a file path, line number, or a query against the
live `echorank` database.

**Headline:** the codebase is in better shape than the brief assumed — branding is clean,
tenant isolation holds on every `[id]` route, no secrets leak into the client bundle, and
the two "known" i18n/styling regressions are already fixed. The real problems are
elsewhere: **nobody can pay you** (Stripe is unconfigured end to end), **three purchased
capability groups have no implementation at all**, and **12 of 21 SEO tools are honest
"coming soon" shells** sold inside paid tiers.

## 2. Known-fragile areas — current state

### 2.1 Stripe: checkout is impossible on every tier

This is the single largest revenue blocker, and it fails at four independent layers:

1. **`STRIPE_SECRET_KEY` is an empty string** in `.env` — not a test key, not a live key.
2. **`STRIPE_WEBHOOK_SECRET` is empty** — `src/app/api/webhooks/route.ts:296-298` logs an
   error and refuses every webhook.
3. **`stripe_prices` has 0 rows** — `getStripePriceId()`
   (`src/lib/stripe/prices.ts:26-37`) returns `null` for every tier/currency/interval.
4. **No checkout code path exists.** `src/lib/stripe/` contains only `prices.ts`. There is
   no `billingPortal.sessions.create` and no `checkout.sessions.create` anywhere in
   `src/`. `/api/billing/route.ts` reads `stripeCustomerId`/`stripeSubscriptionId` but
   never calls Stripe; `/billing`'s "upgrade" is a `confirm()` dialog over a direct plan
   change (`billing/page-client.tsx:74-82`).

Consequence: a tenant's `planType` can be changed **without any payment**. The
`hasPaidPlan` ACTIVE-only guard is sound (`paid-plan.ts`), but nothing connects it to
money. All 7 tenants are `ACTIVE` with 0 subscriptions.

The seed script `scripts/seed-plan-prices-usd.ts` (committed 2026-07-27) is correct and
idempotent but **has never run** — it aborts on the empty key by design.

Webhook tier mapping now includes `ai_visibility` (`stripe/prices.ts:26-30`, fixed
2026-07-27), so that gap is closed *once prices exist*.

### 2.2 GSC Insights: connected, syncing, storing nothing

`gsc_connections` has 1 `ACTIVE` row for `sc-domain:echorank360.com` with
`lastSyncAt = 2026-07-28 05:10` — i.e. it synced **hours ago**. Yet `gsc_query_stats` is
**empty**. Either the sync writes nowhere, or it silently no-ops. This is not "awaiting
accumulation": the sync is running and producing zero rows. Worth a targeted trace of the
sync worker path before shipping GSC Insights to anyone.

Stale comment to fix while you're there:
`src/app/api/public/v1/visibility/summary/route.ts:3-4` says "no GSC connection exists in
the product yet" — untrue since the connection landed.

### 2.3 Competitor snapshots: populating, thinly

3 competitors, 6 snapshots. Working, but 2 snapshots per competitor is not enough to
render a trend. Expect "no data yet" states to dominate for a new tenant.

### 2.4 AI features: no provider key

`OPENAI_API_KEY` and `ANTHROPIC_API_KEY` are both **empty** in `.env`
(`OPENAI_MODEL`/`ANTHROPIC_MODEL` absent entirely). Every `ai_analysis` surface —
`/api/ai/analyze`, `/api/ai/respond`, `/api/ai/reputation` — cannot function. `ai_analysis`
is sold to GROWTH and above (`feature-flags.ts:49`).

### 2.5 Email: no transport

`SMTP_HOST`, `SMTP_USER`, `SMTP_PASS` are all **empty** (`src/lib/visibility-alerts.ts:31-40`).
`ALERT_FALLBACK_EMAIL` is set, but there is nothing to send through. Campaigns
(`campaigns` = 0 rows), review requests, digests and alerts are all inert. `BREVO_API_KEY`
is absent though `/api/webhooks/brevo` exists — a dangling integration.

### 2.6 i18n: materially better than the brief claims

Every `(dashboard)` page except one imports from `lib/i18n`. The single exception,
`visibility/brand-radar/page.tsx`, is a **3-line redirect stub** with no user-visible text
— a false positive. The "/visibility body hardcoded English" and "zinc/teal intelligence
pages" regressions **no longer reproduce**: `grep -rn 'zinc-\|teal-'` across
`src/app/(dashboard)` returns nothing.

Structural caveat, not a bug: the dashboard has **three** catalogs (`en`, `fr`, `de-CH`),
not five. `dashboardLocale()` (`src/lib/i18n/dashboard.ts:13-17`) folds `en-CA → en`,
`fr-CA → fr`, `de* → de-CH`. Any spec asking for five distinct locale catalogs is asking
for unreachable code. Marketing (`src/lib/i18n/pricing.ts:9-18`) does map 8 locales — the
two systems have different locale models, which is a trap for future work.

### 2.7 Metadata: clean

Only `src/app/layout.tsx` defines `metadataBase`/`title` templates/canonical — no
duplicate or conflicting sets found. No stale GSC placeholder tokens: verification is
file-based (`public/google53f8cfb2ee070790.html`) and `layout.tsx:25` documents why there
is no meta tag. The only `PLACEHOLDER` token is
`src/components/seo-tools/mcp-server-client.tsx:21` (`er_api_YOUR_KEY`), which is
intentional example copy.

## 4. Security and correctness

**What holds up well** (verified, no action needed):

- **Tenant isolation:** every one of the 12 `[id]` API routes scopes by `tenantId`. The
  two with the fewest references are still correct: `review-links/[id]/qr/route.ts:14-15`
  and `imports/[id]/route.ts:34-35` both use `findFirst({ where: { id, tenantId } })`.
- **Public v1 + MCP auth:** `authenticatePublicRequest` → `verifyApiKey`
  (`src/lib/api-keys.ts:99,128`), with all downstream queries scoped to `auth.tenantId`
  (e.g. `public/v1/visibility/summary/route.ts:11-14`). Keys stored as SHA-256 hashes.
- **Stripe webhook signature** is verified, with the secret's absence handled explicitly
  (`api/webhooks/route.ts:296-317`).
- **No secrets in the client bundle.** Grepped `.next/static` for `sk_live`/`sk_test`/PEM
  headers/Google key patterns and for the literal values of `INTERNAL_API_SECRET` and
  `DATAFORSEO_PASSWORD` — nothing. Only `NEXT_PUBLIC_SENTRY_DSN` is exposed, correctly.
- **`proxy.ts` public paths are tight.** `publicExactPaths`
  (`src/proxy.ts:40-44`) uses exact matching for the three anonymous `/api/av/*` endpoints
  with a written rationale for why prefix matching would be wrong. No gaps found either way.

**Findings:**

1. **`/api/av/audit` rate limiting is process-local and resets on deploy.**
   `src/app/api/av/audit/route.ts:11` uses a bare `new Map()` with a 1-per-24h cap. Every
   `pm2 restart` wipes it — and this app was restarted 7 times on 2026-07-27 alone. The
   "1 free audit per day" limit is effectively bypassable by waiting for any deploy, and
   costs real sidecar/DataForSEO spend. Its sibling `/api/av/keywords` does this correctly
   via Redis (`route.ts:64-68`). Straight port.

2. **`rate-limit.ts` silently degrades to in-memory.** `src/lib/rate-limit.ts:5,29-31`
   documents a deliberate in-memory fallback when Redis is unavailable. Correct as a
   liveness choice, but a Redis outage downgrades every limiter to per-process counters
   with no alert. At minimum it should log at `warn` once per outage.

3. **A logged-in user with no tenant membership is not redirected.**
   `(dashboard)/layout.tsx:16-32` redirects on `!session?.user`, then calls
   `getCurrentTenant()` (nullable) and only redirects when a `plan` exists. A session with
   zero `TenantMember` rows falls through to pages that assume a tenant — `requireTenant()`
   throws (`src/lib/tenant.ts:49-54`) and the user gets an error page instead of onboarding.

## 5. UX gaps in week one

Walking the golden path per tier against the live data:

**STARTER** (`review_authenticity` only, and it is unbuilt): lands on `/dashboard`. The
whole reputation loop is empty — `feedback` 0, `campaigns` 0, `review_links` 0 — and with
`SMTP_*` empty, creating a campaign sends nothing. There is no working feature behind this
tier today.

**GROWTH** (adds `ai_analysis`, `ai_visibility`, `advanced_analytics`,
`escalation_prediction`): AI surfaces fail closed with no provider key. `ai_visibility`
works — prompt runs are live (newest 04:30 today). `advanced_analytics` and
`escalation_prediction` have ~1 reference each outside config.

**AGENCY** (all 16 features): pays the most, reaches the SEO Tools hub, and finds 12 of 21
tools showing a disabled button and a "coming soon" badge. `sso`, `executive_dashboard`,
`custom_integrations` and `multi_location_intelligence` have no code at all.

**AI_VISIBILITY** ($29, confined to `/visibility`, `/settings`, `/billing`, `/team` by
`plan-routing.ts:21`): the healthiest path. Prompt tracking genuinely works. But
`visibility_audits` is 4 days stale, and GSC Insights renders from an empty
`gsc_query_stats`.

**Cross-cutting dead ends:**

- Every scaffold tool is a lock-with-no-exit: `FeatureScaffold` offers a **disabled** CTA,
  so there is no upgrade path, no waitlist capture, and no "notify me" — a paying user's
  click goes nowhere.
- No tier can self-serve an upgrade, because no checkout exists (§2.1).
- `/intelligence/risk` is unreachable from the UI.

`npx eslint`, and the six `npm run test:*` suites. No file outside this report was created
